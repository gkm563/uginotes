Introduction to Operating Systems

Functions · Classification · Structure · Services · Kernels

What is an Operating System?

Definition
An Operating System (OS) is system software that acts as an intermediary between computer hardware and users. It manages hardware resources and provides a platform for application programs.

Think of the OS as a manager of a large office — it assigns resources (desks = CPU, filing cabinets = memory), resolves conflicts, and ensures no single employee hogs everything.

Primary Functions of an OS

  • Process Management — Create, schedule, and terminate processes.
  • Memory Management — Allocate and deallocate RAM to processes.
  • File System Management — Organize data on storage devices.
  • I/O Management — Control input/output devices.
  • Security & Protection — Authenticate users, isolate processes.
  • Networking — Handle network communication (TCP/IP stacks).
Real-World Example
When you open Chrome on Windows, the OS (Windows 11) allocates RAM to Chrome, schedules CPU time for it, connects it to your Wi-Fi adapter via the network stack, and controls which files Chrome can read — all transparently.

Multiprocessor: Symmetric vs. Asymmetric PYQ 2014-15

Symmetric Multiprocessing (SMP)

  • All processors are equal
  • Each runs its own copy of the OS kernel
  • More robust — any CPU can do any job
  • Example: Modern Intel/AMD multi-core PCs
  • Better load balancing

Asymmetric Multiprocessing (ASMP)

  • Master CPU controls and assigns tasks
  • Slave CPUs execute assigned tasks only
  • Simpler to implement
  • Master can become bottleneck
  • Example: Early mainframe systems

Operating System Structure

1. Layered Architecture PYQ 2014-15, 2017-18, 2023-24

The OS is divided into layers, each built on top of the previous. Layer N uses services of Layer N-1 and provides services to Layer N+1.

Advantages: Modularity, easy debugging (isolate errors to one layer), abstraction. Disadvantage: Performance overhead (each layer adds latency).

2. Monolithic Kernel PYQ 2016-17, 2021-22

Entire OS runs in a single large process in kernel space. All services (file system, device drivers, process management) are in one big block.

Example
Linux kernel is monolithic. All kernel services run in the same address space. This makes it fast (no context switching between kernel components) but a bug in one component can crash the whole kernel.

3. Microkernel

Only essential services (IPC, basic scheduling, memory management) run in the kernel. Everything else (file systems, device drivers) runs in user space as servers.

Monolithic Kernel

  • All services in kernel space
  • Fast — direct function calls
  • Less secure — one bug affects all
  • Example: Linux, MS-DOS

Microkernel

  • Minimal kernel; rest in user space
  • Slower — message passing overhead
  • More secure and stable
  • Example: macOS (Mach), QNX, MINIX

4. Reentrant Kernel

Definition
A kernel is reentrant if multiple processes can be executing kernel code simultaneously. This is essential for time-sharing systems. Linux kernel is reentrant.

Operating System Services PYQ 2021-22

  • Program Execution — Load programs into memory and run them.
  • I/O Operations — Provide a uniform interface to all I/O devices.
  • File-System Manipulation — Read, write, create, delete files and directories.
  • Communications — Inter-process communication (pipes, sockets, shared memory).
  • Error Detection — Handle hardware errors, divide-by-zero, memory violations.
  • Resource Allocation — Fairly distribute CPU, memory, I/O among competing processes.
  • Accounting — Track which users use how much resources (useful in cloud billing — AWS, Azure).
  • Protection & Security — Control access (passwords, file permissions on Linux: chmod 755).

Spooling (Simultaneous Peripheral Operation On-Line) PYQ 2014-15

Definition
Spooling is the process of putting jobs in a buffer (spool) — a special area of memory or disk — where they wait to be processed. The classic example is a print spooler: multiple documents queue up to be printed one at a time.
Real Example
When you print multiple documents from Windows, they all go into the Windows Print Spooler service. You can keep working while they print — the OS handles sequencing.

Section A – Short Answer

Q. What is spooling? 2014-15, 2015-16

▶ Show Answer
Spooling (Simultaneous Peripheral Operation On-Line) places jobs in a buffer (spool) on disk/memory before sending to slow devices like printers. Example: Windows print queue. It overlaps I/O of one job with execution of another, improving CPU utilization.

Q. Define multithreading. 2015-16

▶ Show Answer
Multithreading is the ability of a CPU or single process to execute multiple threads concurrently. Each thread shares the process's code, data, and files but has its own stack and registers. Example: Chrome browser uses separate threads for rendering, networking, and JavaScript execution.

Q. What is the primary function of an operating system? 2023-24, 2024-25

▶ Show Answer
The primary function is to act as an intermediary between users and hardware. Specifically: (1) Resource management — allocate CPU, memory, I/O to processes. (2) Abstraction — hide hardware complexity from users/programs. (3) Control — prevent errors and improper use.

Q. A system has 3 processors and 5 programs ready for execution. In how many ways can processors be assigned? 2024-25

▶ Show Answer
We need to assign 3 processors to 5 programs. Each processor runs one program. This is a permutation: P(5,3) = 5!/(5-3)! = 5×4×3 = 60 ways.

Section B – Long Answer

Q. Explain the layered architecture of OS with advantages and disadvantages. 2014-15, 2017-18, 2023-24

▶ Show Answer
Answer: See the layered architecture diagram above (Layer 1 hardware → Layer 5 user programs).
Advantages: Modularity, abstraction, easier debugging (isolate bugs to one layer), simplicity of construction.
Disadvantages: Performance overhead (must pass through each layer), difficulty in defining clean layer boundaries, some functions span layers.
Example: THE operating system by Dijkstra used 6 layers.

Q. What do you mean by kernel? Describe monolithic and microkernel structures. 2018-19, 2016-17, 2021-22

▶ Show Answer
Kernel: Core part of OS that runs continuously in memory with highest privilege. Manages hardware directly.
Monolithic: All services in one process in kernel mode. Fast but less secure. Examples: Linux, Unix.
Microkernel: Only IPC, basic scheduling, memory mapping in kernel. File systems, drivers in user space as servers. More secure/stable but slower due to message passing. Examples: macOS Mach, MINIX, QNX.

Q. Compare time-sharing and multiprogramming OS concepts. 2023-24

▶ Show Answer
See the comparison table in the notes above. Key difference: multiprogramming switches CPU only on I/O wait (maximizes CPU utilization), while time-sharing switches every time quantum ~10-100ms (minimizes user response time). Time-sharing is an extension of multiprogramming with user interaction.

Q. How does a multiuser OS differ from a multiprocessing system? 2023-24

▶ Show Answer
Multiuser OS: Allows multiple users to use the system simultaneously (via terminals or network). Focus is on user isolation, security, and fair resource sharing. Example: Linux server hosting 100 users.
Multiprocessing OS: Uses multiple CPUs/cores to increase throughput. Focus is on parallel execution of tasks. Multiple CPUs work on different tasks or share one task. Example: Modern AMD Ryzen 12-core PC. A system can be both (multi-core Linux server serving many users).

Concurrent Processes

Process Concept · Mutual Exclusion · Semaphores · Classical Problems · IPC

Process Concept PYQ 2015-16

Definition
A process is a program in execution. It is a dynamic entity — it has a state, resources allocated to it, and code that runs.

Program

  • Passive entity (just code on disk)
  • Stored in a file (.exe, .py)
  • No resources allocated
  • Does not change state
  • Example: Chrome.exe sitting on your SSD

Process

  • Active entity (running program)
  • Loaded into RAM
  • Has CPU registers, stack, heap
  • Changes state (running, waiting...)
  • Example: Chrome.exe after double-clicking

Principle of Concurrency

Concurrency means multiple processes are executing (or appearing to execute) at the same time. On a single CPU, this is achieved by interleaving — switching rapidly between processes. On multi-core systems, true parallelism occurs.

Real Example
On your laptop, while Spotify streams music (process A), Chrome renders a webpage (process B), and Windows Defender scans files (process C) — these are concurrent. On a 4-core CPU, up to 4 processes truly run in parallel at any instant.

Process Generation: fork()

int main() {
    fork();  // Creates 1 child → 2 processes total
    fork();  // Each of 2 creates 1 → 4 processes
    fork();  // Each of 4 creates 1 → 8 processes
    // Total processes = 2^n = 2^3 = 8
}
Exam Formula
After n calls to fork(), total processes = 2n. The number of new child processes = 2n – 1.

Mutual Exclusion & Critical Section

Critical Section
A critical section is a segment of code where a process accesses shared resources (e.g., shared variables, files, hardware). Only one process must execute in its critical section at a time.

Requirements for a Valid CS Solution PYQ 2016-17, 2017-18, 2024-25

  • Mutual Exclusion — If process Pi is in CS, no other process can be in CS.
  • Progress — If no process is in CS, one of the waiting processes must eventually enter.
  • Bounded Waiting — There's a limit on how many times other processes can enter CS before a waiting process does (no starvation).

Dekker's Algorithm PYQ 2016-17, 2014-15, 2023-24

First software solution to the critical section problem for 2 processes. Uses two variables: flag[] (intention to enter) and turn (whose turn it is).

// Process P0
flag[0] = true;
while (flag[1]) {
    if (turn != 0) {
        flag[0] = false;
        while (turn != 0);  // busy wait
        flag[0] = true;
    }
}
// === Critical Section ===
turn = 1;
flag[0] = false;

Key insight: If both want to enter, turn decides — the non-favored process backs off (sets flag to false) and waits.

Peterson's Algorithm PYQ 2015-16, 2014-15

Simpler, more elegant 2-process solution. Uses flag[] and turn.

// Process Pi (other is Pj)
flag[i] = true;
turn = j;                    // Yield to j
while (flag[j] && turn == j); // Wait if j wants and it's j's turn
// === Critical Section ===
flag[i] = false;

Peterson's satisfies all 3 requirements. Remember: It uses polite yielding — "I want to enter, but you go first."

Test-and-Set Instruction PYQ 2017-18

// Hardware atomic instruction
boolean TestAndSet(boolean *target) {
    boolean rv = *target;
    *target = true;
    return rv;
}
// Usage:
while (TestAndSet(&lock));  // Spin until lock is false (available)
// === Critical Section ===
lock = false;

Advantage: Hardware ensures atomicity — no race condition possible. Disadvantage: Busy waiting (wastes CPU cycles). Used in spinlocks in Linux kernel.

Semaphores PYQ 2014-15, 2015-16, 2022-23

Definition
A semaphore is an integer variable (S) accessed only through two atomic operations: wait(S) and signal(S), proposed by Dijkstra. It solves the busy-waiting problem of earlier solutions. 
wait(S):
    while S <= 0;  // busy wait (counting semaphore)
    S--;

signal(S):
    S++;

Better implementation (no busy waiting):

wait(S):
    S.value--;
    if S.value < 0:
        add process to S.list
        block()         // suspend process (no CPU waste!)

signal(S):
    S.value++;
    if S.value <= 0:
        remove process P from S.list
        wakeup(P)       // unblock it
FeatureBinary Semaphore (Mutex)Counting Semaphore
Value range0 or 1 onlyAny non-negative integer
PurposeMutual exclusionControl access to N resources
ExampleProtecting a single printerManaging a pool of 5 DB connections
Initial value1 (unlocked)N (number of resources)
Real-World: Android Binder IPC
Android's Binder driver uses semaphores to manage access to the binder thread pool. When all threads are busy, new requests wait (semaphore = 0). When a thread finishes, it signals (semaphore++), waking up the next waiting request.

Classical Concurrency Problems

1. Producer-Consumer (Bounded Buffer) PYQ 2016-17, 2018-19, 2022-23

Producer generates items into a buffer; Consumer removes items. Buffer has finite capacity N.

Semaphore mutex = 1;     // mutual exclusion for buffer access
Semaphore empty = N;     // number of empty slots
Semaphore full = 0;      // number of filled slots

Producer:
  wait(empty);     // wait if buffer full
  wait(mutex);
  // add item to buffer
  signal(mutex);
  signal(full);    // notify consumer

Consumer:
  wait(full);      // wait if buffer empty
  wait(mutex);
  // remove item from buffer
  signal(mutex);
  signal(empty);   // notify producer
Buffer Problem from PYQ 2024-25
Buffer size = 4. Producer produces 6, Consumer consumes 3. Items in buffer = 6 – 3 = 3. (Buffer can hold 4 max; producer blocks after filling 4; after consumer takes 3, producer can add 3 more → final = 3 items in buffer)

2. Dining Philosophers PYQ 2017-18, 2021-22, 2022-23

5 philosophers sit at a round table. Each needs 2 chopsticks (left and right) to eat. There are only 5 chopsticks (one between each pair).

Problem: If all 5 pick up the left chopstick simultaneously → deadlock (circular wait).

Solution using monitors / Semaphores:

Semaphore chopstick[5] = {1,1,1,1,1};

Philosopher i:
  wait(chopstick[i]);              // pick left
  wait(chopstick[(i+1) % 5]);     // pick right
  // eat
  signal(chopstick[i]);
  signal(chopstick[(i+1) % 5]);

// Deadlock prevention: Allow at most 4 philosophers to sit simultaneously

3. Sleeping Barber Problem

A barbershop with N waiting chairs. If no customer → barber sleeps. If customer arrives and all chairs full → customer leaves. Otherwise customer sits and wakes barber.

Semaphore customers = 0;  // # waiting customers
Semaphore barbers = 0;    // # available barbers
Semaphore mutex = 1;      // for waiting variable
int waiting = 0;

Barber:
  wait(customers);    // sleep if no customers
  wait(mutex);
  waiting--;
  signal(barbers);
  signal(mutex);
  cut_hair();

Customer:
  wait(mutex);
  if waiting < N:
    waiting++;
    signal(customers);  // wake barber
    signal(mutex);
    wait(barbers);      // wait for barber
    get_haircut();
  else:
    signal(mutex);      // leave (full)

Inter-Process Communication (IPC) PYQ 2015-16, 2021-22

Shared Memory

  • Processes share a common memory region
  • Fast — no kernel involvement after setup
  • Requires synchronization (semaphores)
  • Example: Producer-Consumer buffer
  • Linux: shmget(), shmat()

Message Passing

  • Processes send/receive messages via kernel
  • Slower — kernel mediates each message
  • No shared memory needed (distributed OK)
  • Example: Android Binder, Unix pipes
  • Easier to implement correctly

Other IPC Mechanisms

  • Pipes — Unidirectional byte stream. ls | grep txt in Linux creates a pipe.
  • Named Pipes (FIFOs) — Like pipes but have a name and can be used by unrelated processes.
  • Sockets — Network communication. Chrome uses sockets to talk to web servers.
  • Signals — Asynchronous notifications. Ctrl+C sends SIGINT signal in Linux.
  • Message Queues — Messages queued in kernel. Processes post/retrieve independently.

📝 Unit 2 – Question Bank

Q. What is Busy Waiting? How to overcome it using semaphores? 2017-18, 2015-16, 2022-23

▶ Show Answer
Busy Waiting: A process continuously checks a condition in a loop (spin-lock) wasting CPU cycles. Example: while(flag) ;
Solution with semaphores: Instead of looping, process calls block() which suspends it and removes it from CPU. When the condition is met, wakeup() is called. This way, CPU time is freed for other processes.

Q. Two semaphores S1, S2 both = 1. P1: wait(S1); wait(S2). P2: wait(S2); wait(S1). Explain deadlock. 2024-25

▶ Show Answer
Deadlock sequence: 1) P1 executes wait(S1) → S1=0. 2) Context switch. 3) P2 executes wait(S2) → S2=0. 4) P1 tries wait(S2) → S2=0, P1 blocks. 5) P2 tries wait(S1) → S1=0, P2 blocks. Both processes wait for each other forever → deadlock. This is a circular wait condition.

Q. Compare Dekker's and Peterson's algorithms. 2023-24

▶ Show Answer
See table in notes above. Key points: Both are software solutions for 2 processes. Both use busy waiting. Peterson's is simpler (published 1981, 16 years after Dekker 1965). Peterson uses "polite yielding" (turn = j), while Dekker uses contention resolution (back off and retry). Both satisfy mutual exclusion, progress, and bounded waiting.

Q. In Producer-Consumer with buffer size 4: Producer produces 6, Consumer consumes 3. Items in buffer? 2024-25

▶ Show Answer
Step by step: Buffer capacity = 4. Producer adds 1,2,3,4 → buffer full (4 items). Producer tries to add 5th → blocked (empty semaphore = 0). Consumer removes 3 items → buffer = 1 item, signals producer. Producer can now add 2 more (items 5 and 6) → buffer = 3 items. Final answer: 3 items in buffer.

Q. Process executes fork(); fork(); fork(); How many total processes? 2024-25

▶ Show Answer
Formula: n fork() calls → 2^n total processes. With 3 forks: 2^3 = 8 total processes (including original). New child processes created = 8 – 1 = 7.

Deadlock PYQ 2017-18, 2021-22, 2022-23, 2024-25

Definition
A deadlock is a situation where a set of processes are permanently blocked — each waiting for a resource held by another process in the set. None can proceed.

Four Necessary Conditions (Coffman Conditions)

  • Mutual Exclusion — At least one resource must be non-shareable (e.g., printer).
  • Hold and Wait — A process holds ≥1 resource and waits for more.
  • No Preemption — Resources cannot be forcibly taken from a process.
  • Circular Wait — P1 waits for P2, P2 waits for P3, ..., Pn waits for P1.
Remember
All four conditions must hold simultaneously for deadlock to occur. Breaking any one prevents deadlock.

Banker's Algorithm (Deadlock Avoidance) PYQ 2017-18, 2015-16, 2022-23

Concept
Like a bank that never allocates money such that it can't satisfy all customers. The OS only allocates resources if the resulting state is safe (∃ a sequence where all processes can finish).

Key matrices:

  • Allocation[i][j] — How much of resource j process i currently holds.
  • Max[i][j] — Maximum demand of resource j by process i.
  • Need[i][j] = Max[i][j] – Allocation[i][j]
  • Available[j] — Currently free units of resource j.

Safety Algorithm Steps:

  1. Find process whose Need ≤ Available.
  2. If found: "pretend" it runs, release its allocation → Available += Allocation.
  3. Repeat until all processes finish (safe) or none can proceed (unsafe).
PYQ 2022-23 – Banker's Example (3 resources A,B,C)
Available = [2,1,0]
Need matrix: P0=[3,2,2], P1=[1,0,2], P2=[5,-1,-2]→invalid… (see full table in PYQ notes)
Safe sequence: Start with process whose Need ≤ Available. P1 need=[1,0,2] > [2,1,0]? P1 needs 2 of C but only 0 available → skip. P0 need=[3,2,2] > available → skip. P3 need=[7,4,3]... Try each systematically.

📝 Unit 3 – Question Bank

Q. List three components stored in a PCB. 2024-25

▶ Show Answer
1. Process ID (PID) — unique identifier. 2. Program Counter — address of next instruction to execute. 3. CPU Register values — saved state of all registers (for context switching). Other valid answers: process state, memory limits, scheduling priority, open file list.

Q. What do you mean by safe state and unsafe state? 2021-22

▶ Show Answer
Safe state: A state is safe if there exists a safe sequence — an ordering of all processes such that each can obtain its maximum resources and complete. Unsafe state: No such sequence exists; deadlock may (not necessarily will) occur. The OS avoids unsafe states using Banker's Algorithm.

Q. A system has 9 tape drives. Current: P1=3, P2=1, P3=3. Max: P1=7, P2=6, P3=5. Is system safe? 2024-25

▶ Show Answer
Total allocated = 3+1+3 = 7. Available = 9-7 = 2.
Need: P1=7-3=4, P2=6-1=5, P3=5-3=2.
Safety check: P3 needs 2 ≤ available(2) → P3 runs, releases 3 → Available=5. P1 needs 4 ≤ 5 → P1 runs, releases 3 → Available=8. P2 needs 5 ≤ 8 → P2 runs. Safe sequence: P3→P1→P2. System is SAFE, NOT deadlocked. Answer: Option 2.

Q. Compare FCFS, SJF, and Round Robin scheduling algorithms. 2024-25

▶ Show Answer
See the scheduling table in notes. Key points: FCFS = simple, non-preemptive, convoy effect, no starvation. SJF = optimal average WT, non-preemptive, needs burst time knowledge, starvation possible. RR = preemptive, fair, best for time-sharing, performance depends heavily on time quantum Q (too small = too many context switches; too large = behaves like FCFS).

Fragmentation PYQ 2016-17, 2022-23

Internal Fragmentation

  • Wasted space inside an allocated partition
  • Happens in fixed partitioning and paging
  • Example: 100 KB partition, 90 KB process → 10 KB wasted inside
  • Cannot be reused by other processes

External Fragmentation

  • Wasted space outside allocations (free holes)
  • Happens in variable partitioning
  • Total free = enough, but not contiguous
  • Solution: Compaction (move processes together)

Paging & Segmentation PYQ 2018-19, 2022-23, 2023-24

Paging

Physical memory divided into equal-size frames. Logical memory divided into equal-size pages. A page table maps pages to frames.

TLB (Translation Lookaside Buffer)

A high-speed cache for the page table. Most lookups hit the TLB and skip the slow main memory page table access.

Effective Access Time (EAT) formula:

EAT = α × (TLB_time + memory_time) + (1-α) × (TLB_time + 2 × memory_time)
Where α = hit ratio
PYQ Calculation 2022-23
TLB access = 100ns, Memory access = 80ns more (total 180ns for memory). Hit ratio = α.
EAT = 125ns → α(100+80) + (1-α)(100+80+80) = 125 → 180α + 260(1-α) = 125 → 180α + 260 - 260α = 125 → -80α = -135 → α = 135/80 ≈ 0.9375 (93.75% hit ratio)

Virtual Memory & Demand Paging PYQ 2016-17, 2022-23

Virtual Memory
A technique that allows execution of processes that are not completely in memory. The logical address space can be larger than physical memory. Pages are loaded on demand.
Real Example
Your laptop has 8GB RAM. You run Photoshop (2GB), Chrome (3GB), and try to open a 6GB video — total 11GB > 8GB physical. The OS uses virtual memory (swap space on SSD) to keep only active pages in RAM. Rarely used parts are swapped to disk.

Demand Paging

Pages are loaded into memory only when accessed (not all at start). A page fault occurs when a referenced page is not in memory.

Page Fault Handling:

  1. Process accesses a page → check valid bit in page table.
  2. Valid bit = 0 → page fault trap → kernel.
  3. Kernel finds page on disk.
  4. Load page into free frame.
  5. Update page table, set valid bit = 1.
  6. Restart the faulting instruction.

Thrashing PYQ 2017-18, 2016-17, 2022-23

Thrashing
Thrashing occurs when a process spends more time paging than executing — it constantly causes page faults. The OS is so busy swapping pages that useful work stops.

Cause: Too many processes in memory → each has too few frames → high page fault rate → CPU utilization drops → OS admits more processes → even worse.

Solution: Working Set Model — keep only the "working set" (recently used pages) of each process in memory. Suspend processes if total working sets exceed available frames.

Locality of Reference

Programs tend to access the same set of addresses repeatedly (temporal locality) and nearby addresses together (spatial locality). This is why LRU and demand paging work well in practice.

Belady's Anomaly
In FIFO, adding more frames can sometimes increase page faults! This is Belady's Anomaly. LRU and OPT are stack algorithms and do NOT suffer from this anomaly.

PYQ 2024-25 – Page Table Size Calculation

32-bit logical address, 20-bit physical, page size = 2048 bytes = 2^11 bytes
Offset bits = log2(2048) = 11 bits
Page number bits = 32 - 11 = 21 bits
Max entries in page table = 2^21 = 2,097,152 entries

📝 Unit 4 – Question Bank

Q. What is the purpose of a page replacement algorithm? 2024-25

▶ Show Answer
When a page fault occurs and memory is full, a page replacement algorithm decides which page to evict (remove) from memory to make space for the new page. The goal is to minimize the total number of future page faults, improving system performance and reducing disk I/O.

Q. What do you mean by Belady's anomaly? Which algorithm suffers from it? 2017-18

▶ Show Answer
Belady's Anomaly: The counterintuitive phenomenon where increasing the number of memory frames leads to more page faults (not fewer). Only FIFO suffers from this. LRU and Optimal do not (they are stack algorithms). To fix: Don't use FIFO; use LRU or clock algorithm instead.

Q. Reference string: 1,2,3,4,2,1,5,6,2,1,2,3,7,6,3,2,1,2,3,6. FIFO, LRU, OPT with 3 frames. 2015-16, 2017-18

▶ Show Answer
FIFO (3 frames): Page faults = 16
LRU (3 frames): Page faults = 14
OPT (3 frames): Page faults = 11 (minimum possible)
For 4 frames: FIFO=14, LRU=11, OPT=8. Note: OPT always gives minimum, LRU ≤ FIFO typically, and OPT ≤ LRU always.

Q. What causes thrashing? How to eliminate it? 2017-18, 2016-17

▶ Show Answer
Cause: Too many processes competing for too few frames → each process lacks enough pages → high page fault rate → OS spends all time paging → CPU utilization drops → degree of multiprogramming increases → worsens problem.
Solutions: (1) Working Set Model — allocate frames = working set size. (2) Page Fault Frequency control — if fault rate too high, allocate more frames; if too low, remove frames. (3) Reduce degree of multiprogramming by swapping out some processes.

I/O Management

I/O Buffering PYQ 2021-22, 2017-18

Buffering
A buffer is a memory area that holds data while it's transferred between devices (or between device and CPU). It smooths out speed differences.
  • Single Buffering: One buffer — CPU and device share it. CPU waits while device fills buffer.
  • Double Buffering: Two buffers — device fills buffer 1 while CPU processes buffer 2. Then swap. Better overlap.
  • Circular Buffering: Ring of N buffers for high-speed streams (video streaming, audio capture).
Real Example
When you stream YouTube on Chrome, the browser pre-buffers several seconds of video ahead. This is circular buffering — new video chunks are fetched into buffers while older ones are displayed.

DMA (Direct Memory Access)

DMA allows I/O devices to transfer data directly to/from memory without CPU involvement. The CPU only initiates the transfer and gets an interrupt when done.

Example
When you copy a large file from USB drive on Linux, the USB controller uses DMA to move data directly to RAM. The CPU just starts the transfer and handles the completion interrupt — it's free to run other code during the transfer.

File Systems PYQ 2018-19, 2021-22

File Concept & Operations

A file is a named collection of related information recorded on secondary storage. The OS provides a uniform interface regardless of the underlying storage device.

File attributes: Name, identifier (inode number), type, location, size, protection, timestamps.

File operations: Create, Read, Write, Reposition (seek), Delete, Truncate, Open, Close.

File Access Methods

  • Sequential Access — Read bytes in order (magnetic tape, log files). read() advances file pointer automatically.
  • Direct (Random) Access — Jump to any position. seek(n); read(); Database files use this.
  • Indexed Access — Use an index to find records quickly. Database index files.

File Allocation Methods PYQ 2017-18, 2023-24

MethodHow it worksProsCons
ContiguousFile occupies consecutive disk blocksFast sequential & random access; simple directory entry (start, length)External fragmentation; file size must be known at creation
LinkedEach block contains pointer to next blockNo external fragmentation; file can grow dynamicallyNo random access (must follow chain); pointer overhead; reliability (lost pointer = lost data)

Real Example
Linux ext4 uses a variant of indexed allocation (inodes with direct, single-indirect, double-indirect, triple-indirect block pointers). FAT (Windows) uses linked allocation via a File Allocation Table.

Directory Structures PYQ 2014-15, 2015-16

  • Single-level: All files in one directory. Simple but name conflicts for multiple users.
  • Two-level: One directory per user (Master File Directory → User File Directory). Solves name conflict.
  • Tree-structured: Hierarchical. /home/student/notes/os.pdf in Linux. Most common today.
  • Acyclic Graph: Allows sharing (symbolic links, hard links in Linux). Multiple paths to same file.

Free Space Management

  • Bit Vector (Bitmap): 1 bit per disk block; 1=free, 0=allocated. Easy to find contiguous blocks. Linux ext4 uses this.
  • Linked List: Chain of free blocks. No wasted space but hard to find contiguous blocks.
  • Grouping: Store addresses of n free blocks in first free block. More efficient traversal.
  • Counting: Store (first free block, count) pairs. Efficient for contiguous allocations.

File System Protection & Security PYQ 2021-22

  • Access Control List (ACL): Specify exactly who (user/group) can do what (read/write/execute) on each file.
  • Access Matrix: 2D table — rows=subjects (users/processes), columns=objects (files). Linux chmod implements simplified 3×3 version (owner/group/others × r/w/x).
  • Capability Lists: Per-user list of permitted operations on objects.
Linux Example
chmod 755 file.sh → Owner: read+write+execute (7=111), Group: read+execute (5=101), Others: read+execute. This is the access matrix in action.

📝 Unit 5 – Question Bank

Q. Define seek time and rotational latency. 2018-19, 2021-22

▶ Show Answer
Seek time: Time required to move the read/write head to the desired track (cylinder). This is typically the dominant component of disk access time (3-15ms for HDDs). Rotational latency: Time waiting for the desired sector to rotate under the read/write head. Average = half revolution time. At 7200 RPM: avg latency = 60s/7200/2 = 4.17ms.

Q. Explain RAID 0, RAID 1, and RAID 5 in detail. 2024-25

▶ Show Answer
See the RAID table above. Key exam points: RAID 0 = pure striping, no redundancy, max performance. RAID 1 = mirroring, 100% redundancy, 50% efficiency. RAID 5 = best balance — striping with distributed parity (1 disk overhead), can survive 1 disk failure, reads are fast, writes are slower due to parity recalculation. Most enterprise storage uses RAID 5 or 6.
